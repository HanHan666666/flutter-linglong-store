# 应用持续忽略更新设计

## 背景

当前应用更新能力由 `UpdateApps` 统一计算可更新列表，并同时驱动更新页、侧栏更新数量、应用卡片“更新/打开”状态、详情页状态和“全部更新”范围。用户目前无法排除不希望升级的应用，因此每次启动检查、手动检查或刷新后，这些应用都会重新出现在待更新列表中。

本功能允许用户按应用持续忽略更新。忽略后，无论后续发布多少新版本，该应用都不再参与商店的更新检查和更新提示，直到用户在更新页主动恢复。忽略规则仅保存在本机，不改变服务端数据，也不改变 `ll-cli` 的行为。

## 目标

- 用户可从更新列表行级“更多”菜单忽略某个应用的后续更新。
- 忽略规则以 `appId` 为唯一身份，跨版本、架构、仓库、module、卸载和重装持续生效。
- 启动检查、手动检查、更新页刷新和应用集合变更后的检查都跳过已忽略应用。
- 已忽略应用不进入更新列表、侧栏更新数量、卡片更新状态和“全部更新”范围。
- 更新页头部提供低强调度、始终可发现的“已忽略（N）”入口。
- 用户可在轻量管理弹窗中查看记录并逐项恢复更新提醒。
- 功能不得新增后端接口、`ll-cli` 调用、轮询、定时器或卡片级全局 Provider 订阅。

## 非目标

- 不支持“仅忽略当前版本”；忽略始终针对应用并持续生效。
- 不提供按架构、仓库、channel 或 module 分别忽略的能力。
- 忽略操作不取消已经排队或正在执行的更新任务。
- 恢复更新提醒不自动开始升级，只重新允许应用参与更新检查。
- 不把忽略记录同步到用户账号或其他设备。
- 不新增服务端忽略状态、更新接口参数或统计上报。

## 现有架构结论

`updateAppsProvider` 是更新状态的唯一事实来源。以下消费者均从该 Provider 派生：

- `UpdateAppPage` 渲染可更新应用和“全部更新”。
- `MenuBadgeProvider` 计算侧栏更新数量。
- `ApplicationCardStateIndex` 决定已安装应用显示“更新”还是“打开”。
- 应用详情页根据同一更新列表解析更新状态。
- 启动流程和 `AppCollectionSyncService` 触发更新检查。

因此忽略逻辑必须收敛在应用层统一入口和 `UpdateApps` 检查边界，禁止在各个页面、红点或卡片消费者中重复过滤。

当前应用已经在 `main.dart` 中初始化并注入 `SharedPreferences`，`GlobalApp` 和 `Setting` 也采用同步恢复本地设置的模式。忽略更新应复用该基础设施，确保首轮更新检查开始前即可读取忽略集合。

## 方案比较

### 方案一：独立忽略状态、存储与操作入口

新增独立的忽略记录模型、本地存储模块、持久化 Provider 和应用层操作入口。`UpdateApps` 只读取忽略集合完成过滤，UI 只调用统一操作入口。

优点：

- 忽略偏好与远端更新检查职责分离。
- 持久化、并发过滤、业务编排和 UI 可独立测试。
- 不会让语言、主题等全局设置消费者因忽略列表变化而重建。
- 后续若增加批量恢复等管理能力，可以在同一边界内扩展。

代价是增加少量专用文件和 Provider。

### 方案二：合并到 `UpdateApps`

由 `UpdateApps` 同时处理远端请求、版本比较、忽略持久化和管理列表。

该方案文件数量少，但会把远端状态与本地用户偏好混为一体，使 Provider 职责过重，并增加检查更新、写入失败和管理弹窗之间的测试耦合，不采用。

### 方案三：写入全局 `UserPreferences`

把忽略记录加入现有全局偏好 JSON。

该方案可以复用已有序列化，但每次忽略或恢复都会更新完整全局状态，让语言、主题、字号等无关消费者参与重建；忽略列表也不是全局外观偏好，不采用。

最终采用方案一。

## 数据模型与持久化

### 忽略记录

每条记录保存以下字段：

| 字段 | 用途 |
| --- | --- |
| `appId` | 唯一身份和更新过滤依据 |
| `appName` | 管理弹窗展示快照 |
| `icon` | 管理弹窗图标快照，可空 |
| `ignoredVersion` | 用户执行忽略时的已安装版本 |
| `ignoredAt` | 忽略时间戳，用于稳定排序 |

`appId` 是唯一业务键。重复记录恢复时按 `appId` 去重，保留 `ignoredAt` 更新的一条；管理弹窗按 `ignoredAt` 从新到旧排列。

保存名称、图标和忽略时版本是为了让应用卸载后仍可在弹窗中识别和恢复该记录。应用卸载、重新安装、外部升级或本机已安装实例变化都不会自动更新或删除这份快照，也不会解除忽略。

### 存储格式

使用独立的版本化 SharedPreferences key：

`linglong-store-ignored-updates-v1`

值为 JSON 列表。版本号放在 key 中，后续数据结构发生不兼容变化时使用新 key 并通过数据迁移处理，避免在现有格式上隐式改变语义。

本地存储模块负责：

- 从已注入的 `SharedPreferences` 同步读取字符串。
- 对 JSON 顶层和每条记录进行类型校验。
- 单条记录损坏时记录警告并跳过该条，不能让整个列表失效。
- 顶层 JSON 损坏时回退为空列表并记录可诊断日志。
- 按 `appId` 去重并输出稳定顺序。
- 写入完整快照，并把 SharedPreferences 返回的成功结果传给上层。

解析发生在 SharedPreferences 的内存数据上，不执行目录扫描或额外文件 I/O。

### 状态结构

持久化 Provider 使用 `keepAlive`，在 `build` 阶段同步恢复记录。状态同时提供：

- 按忽略时间排序的只读记录列表，供管理弹窗使用。
- `Set<String>` 形式的 `appId` 索引，供检查更新进行 O(1) 判断。
- 忽略数量，供头部入口展示。

状态只在本地写入成功后更新。写入失败时保留旧状态并返回失败结果，禁止出现当前会话看似成功、重启后丢失的假成功。

所有忽略和恢复写入必须在 Provider 内串行化，并在轮到当前操作执行时基于最新状态重新计算完整快照。管理弹窗允许用户连续恢复不同应用，但并行触发的界面事件不能形成多个彼此覆盖的“读旧状态后写完整列表”操作。

## 应用层统一操作入口

新增忽略更新应用服务或控制器，作为 UI 执行忽略和恢复的唯一入口。页面和弹窗不得分别拼接持久化、更新列表移除和重新检查逻辑。

### 忽略

1. 校验 `appId` 非空。
2. 防御性检查该应用是否已经进入安装/更新队列或正在执行。
3. 以当前 `UpdatableApp` 创建忽略记录并持久化。
4. 持久化成功后更新忽略状态。
5. 调用 `UpdateApps.removeApp(appId)` 立即移除当前可更新项。
6. 返回明确结果，供 UI 显示成功、任务活跃或存储失败提示。

忽略成功后，现有消费者会随 `updateAppsProvider` 自动同步：

- 更新页移除该行。
- 侧栏更新数量减少。
- 应用卡片和详情页不再显示可更新状态。
- “全部更新”不再包含该应用。

### 恢复

1. 从持久化记录中删除指定 `appId`。
2. 持久化成功后更新忽略状态并从管理弹窗移除该行。
3. 复用 `AppCollectionSyncService`，先刷新 `ll-cli list --json` 对应的已安装快照，再重新检查更新。
4. 如果应用当前仍有新版本，它重新进入更新列表并同步侧栏和卡片状态。
5. 如果重新检查失败，忽略记录仍保持已恢复；提示用户稍后手动检查，禁止为了网络错误重新写回忽略状态。

恢复只改变更新提醒资格，不自动入队升级。

## 更新检查过滤与并发规则

`UpdateApps.checkUpdates()` 使用双重过滤：

1. 远端调用前读取当前忽略 `appId` 集合，从已安装应用批次中排除已忽略应用。被忽略应用不会发送给更新接口。
2. 远端结果转换为 `UpdatableApp` 并准备写入状态前，再读取一次最新忽略集合并过滤结果。

第二次过滤用于处理以下竞态：

1. 更新检查已经发出网络请求。
2. 用户在请求返回前忽略某个应用。
3. 旧请求包含该应用并返回可更新结果。

如果只在请求前过滤，旧请求会把刚忽略的应用重新放回列表。最终落状态过滤与现有 `_latestRequestId` 共同保证：

- 旧检查请求不能覆盖新检查请求。
- 请求期间新增的忽略规则不能被旧结果覆盖。

忽略集合发生变化不主动触发新的网络请求。忽略通过乐观移除立即收敛 UI；恢复才执行一次现有统一刷新链路。

## 界面设计

### 更新页头部入口

在现有更新页头部操作区加入始终可见的 `已忽略（N）` 入口：

- 使用文字型低强调按钮。
- 使用中性 `onSurfaceVariant` 文字色。
- 不使用填充背景、主题强调色或醒目图标。
- 悬停和键盘聚焦时提供轻量反馈。
- 数量为 0 时仍可点击并打开空态弹窗，保证入口可发现。
- 不改变“检查更新”和“全部更新”的现有主次关系。

### 更新列表行级操作

在每行“更新”按钮旁增加 `⋮` 更多菜单，复用项目已有 `PopupMenuButton` 交互。菜单项为“忽略此应用更新”。

应用存在 pending、downloading 或 installing 任务时，更多菜单中的忽略动作不可用。忽略不承担取消任务语义。

忽略属于可逆、非破坏性操作，不增加确认弹窗。成功后显示轻提示：

“已忽略该应用的后续更新，可在已忽略中恢复。”

菜单按钮和菜单项需要阻止事件继续触发行点击，避免误进入详情页。

### 已忽略管理弹窗

点击头部入口打开轻量管理弹窗：

- 标题为“已忽略的更新”。
- 使用 `A11yFocusScope` 隔离弹窗与背景焦点。
- 使用有界高度的 `ListView.builder` 渲染记录，避免列表增长后一次构建所有行。
- 每行展示应用图标、应用名、`appId` 和“忽略时版本”。
- 每行提供低强调度文字按钮“恢复更新提醒”。
- 恢复进行中只禁用当前行并显示轻量 loading，不阻塞其他记录。
- 空列表展示“暂无已忽略的应用”及简短说明。
- 弹窗提供明确的关闭入口，并支持 Escape。

恢复后弹窗保持打开，便于用户连续管理；对应行在本地写入成功后移除。重新检查出的更新在弹窗背后的更新页同步刷新，用户关闭弹窗后即可看到。

### 国际化与无障碍

所有新增可见文案、Tooltip 和 `Semantics.label` 进入中英文 l10n，禁止硬编码业务文案。

更多菜单、头部入口、恢复按钮和关闭按钮必须：

- 支持 Tab 聚焦和 Enter/Space 激活。
- 提供明确、包含应用名称的无障碍标签。
- 满足至少 48×48 或 48px 高的交互尺寸。
- 将纯装饰图标通过 `ExcludeSemantics` 排除。

## 错误处理

| 场景 | 行为 |
| --- | --- |
| 忽略记录写入失败 | 不移除更新行，不改变忽略状态，显示操作失败 |
| 恢复记录写入失败 | 保留弹窗记录和忽略状态，显示操作失败 |
| 恢复持久化成功、更新检查失败 | 记录保持已恢复，提示稍后重试 |
| 单条持久化记录损坏 | 跳过损坏条目并记录警告，其余记录正常恢复 |
| 顶层 JSON 损坏 | 回退为空列表并记录错误，不阻断应用启动 |
| 应用已在更新队列 | 拒绝忽略，不取消、不移除任务 |
| 重复忽略或恢复 | 按 `appId` 幂等处理，不产生重复记录或异常 |

## 性能设计

- SharedPreferences 已在应用启动前初始化，忽略状态同步恢复不新增磁盘扫描。
- 检查更新使用预构建 `Set<String>` 做 O(1) 过滤。
- 已忽略应用不进入更新接口请求体，减少无效传输和后端比较。
- 管理弹窗仅在用户打开时构建，并使用 builder 列表。
- 不新增 Timer、轮询、后台任务或额外更新请求。
- 不让应用卡片直接订阅忽略 Provider；卡片继续只消费页面级 `ApplicationCardStateIndex`。
- 忽略和恢复只更新必要 Provider，避免修改完整 `GlobalAppState` 或 `SettingState`。

## 测试设计

### 单元测试

忽略存储和 Provider：

- 空数据首次恢复。
- 合法记录同步恢复和排序。
- 重复 `appId` 去重。
- 单条损坏记录跳过。
- 顶层 JSON 损坏回退。
- 写入失败时状态不变。
- 忽略跨版本、卸载和重装持续保留。
- 重复忽略和重复恢复保持幂等。
- 快速连续恢复多条记录时串行写入且不丢失其他变更。

更新检查：

- 远端请求参数不包含已忽略 `appId`。
- 请求期间新增忽略时，最终结果仍排除该应用。
- 全部应用被忽略时不调用远端更新接口。
- 现有最新已安装版本选择、最高远端版本选择和 request ID 竞态逻辑无回归。

统一操作入口：

- 忽略成功后持久化并立即移除更新项。
- 活跃任务阻止忽略。
- 恢复成功后按“已安装快照 → 更新检查”顺序刷新。
- 恢复后检查失败不回滚恢复选择。

### Widget 测试

- 头部始终显示低强调度“已忽略（N）”入口。
- 数量为 0 时可打开空态弹窗。
- 更多菜单可执行忽略。
- 活跃任务下忽略动作不可用。
- 忽略成功后行、数量和“全部更新”范围同步变化。
- 管理弹窗展示快照信息并支持逐项恢复。
- 恢复期间只禁用当前行。
- 弹窗焦点隔离、语义标签、键盘操作和最小交互尺寸正确。
- 中英文文案和长应用名称下布局无溢出。

- `flutter analyze` 必须为 0 error、0 warning。
- 运行忽略更新、更新 Provider、更新页、菜单红点、卡片状态相关测试。
- 运行全量 `flutter test`。

## 验收标准

- 用户从更新列表更多菜单忽略应用后，该应用立即消失且重启后仍保持忽略。
- 被忽略应用不发送给更新接口，也不计入更新页、侧栏红点、卡片更新状态和“全部更新”。
- 新版本发布、应用卸载重装或外部升级不会自动解除忽略。
- 更新页头部始终能找到低强调度的“已忽略（N）”入口。
- 管理弹窗在应用已卸载时仍能用快照展示并恢复记录。
- 恢复后不自动升级；若存在更新，则在一次成功检查后重新出现。
- 请求期间执行忽略不会被旧网络结果覆盖。
- 本地持久化失败不会造成界面与重启后状态不一致。
- 无新增后端接口、`ll-cli` 调用、轮询或卡片级性能负担。
- 静态分析、相关测试和全量测试全部通过。
