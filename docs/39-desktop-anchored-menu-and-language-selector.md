# 桌面锚点菜单与折叠语言选择器设计

> 状态：已确认，作为桌面轻量操作菜单和设置页语言选择的统一实现约定
>
> 适用范围：Linux 桌面端三点菜单、紧邻触发控件的轻量操作菜单、设置页语言选择
> 关联文档：`docs/03b-ui-layout-components.md`、`docs/38-arb-driven-linux-metadata.md`

## 1. 背景

设置页当前把所有受支持语言渲染为一组 `RadioListTile`。这种结构在四种语言时尚可
使用，但页面高度会随新增语言线性增长，语言设置也会逐渐挤占主题、字体和缓存等设置
的可视空间。

项目的更新卡片、通用应用卡片和仓库管理曾同时直接使用 Material 的旧式路由菜单。
Flutter 3.41 中该组件通过 `PopupRoute` 打开菜单，默认执行
300ms 动画，并让菜单项在动画的不同区间分段淡入。单项菜单也会等待动画进度后才
完整出现，因此用户会明显感到点击反馈滞后。

继续在各页面分别调整旧组件只能缓解单个入口，无法统一菜单的视觉、
键盘行为、无障碍和性能边界。需要建立一个应用级锚点菜单原语，并在它之上实现只负责
Locale 业务的语言选择器。

## 2. 目标

1. 使用 Flutter Material 3 推荐的 `MenuAnchor` 替代项目内所有旧式路由菜单，消除
   基于路由的 300ms 展开等待。
2. 菜单显示和关闭保持同步，不增加自定义展开、缩放或淡入动画；悬停反馈仍由 Material
   状态层提供。
3. 集中维护菜单宽高、圆角、边框、阴影、选中态、禁用态和最小交互尺寸。
4. 设置页只显示当前语言，点击后在锚定弹层中展示完整语言列表，页面高度不再随语言数
   量增长。
5. 语言列表继续完全来源于 `selectableAppLocales`，新增 ARB 后不修改设置页代码。
6. 保留鼠标、键盘、焦点返回、点击外部关闭和屏幕阅读器语义。
7. 不引入新的第三方依赖，不按 DDE、GNOME、KDE 或发行版分支。

## 3. 非目标

- 不替换 `flutter_desktop_context_menu` 提供的原生右键菜单。右键上下文菜单与控件锚点
  菜单属于不同交互语义，继续按现有边界维护。
- 不在本阶段加入语言搜索。当前语言规模使用带最大高度的滚动菜单足够；若正式语言超过
  可快速浏览的规模，搜索只在语言选择器内部扩展。
- 不自行实现弹层定位、屏幕边缘避让、焦点树或键盘导航。
- 不修改 ARB 发现、Flutter l10n 生成和 Linux 元数据生成链路。
- 不把菜单开关状态放入 Riverpod 或其他全局状态。

## 4. 方案选择

### 4.1 保留旧式路由菜单并关闭动画

改动最少，但仍保留 Navigator Route、旧式 API 和每个页面独立定义菜单样式的问题。
它适合作为短期止痛，不适合作为项目的长期组件边界。

### 4.2 统一封装 `MenuAnchor`（采用）

`MenuAnchor` 使用 Flutter Overlay 锚定菜单，默认同步显示，不包含旧组件的路由动画。
它同时负责屏幕边缘避让、方向键、Escape、焦点和点击
外部关闭，能够在不重复实现复杂桌面交互的情况下获得直接反馈。

项目新增 `AppAnchoredMenu<T>` 和结构化菜单项模型。Presentation 页面只声明动作值、
文案、图标和可用状态，不直接接触菜单布局细节。

### 4.3 自定义 `OverlayPortal + ListView`

可以按需懒构建海量菜单项，但需要自行维护窗口边缘定位、RTL、显示器缩放、焦点、键盘、
点击外部关闭和语义树。当前菜单规模无法抵消这部分维护成本，只有 Profile 证明确实存在
无法由 `MenuAnchor` 解决的帧超时后才重新评估。

### 4.4 原生 GTK 菜单

原生 GTK 菜单适合 Linux 右键上下文操作，但它通过平台通道传递动作，外观会随桌面环境
变化，也无法自然表达设置字段和单选语义。语言选择及按钮三点菜单不采用该方案。

## 5. 组件边界

```text
AppAnchoredMenu<T>
├── UpdateAppItem：忽略此应用更新
├── AppCard：页面注入的应用操作
├── RepositoryManagementTab：仓库操作
└── AppLanguageSelector
    └── SettingPage：只负责提交 Locale 变更
```

### 5.1 `AppAnchoredMenu<T>`

通用组件负责：

- 持有 `MenuController`，让触发控件只调用统一的开关入口。
- 把结构化动作渲染为 `MenuItemButton`，选择动作前先同步关闭弹层。
- 支持普通动作、禁用动作、选中动作和分隔线。
- 统一使用至少 48px 的菜单项高度。
- 为弹层设置最大高度；项目已有菜单项数量较少时直接构建，超过高度后由 SDK 菜单容器
  滚动，不向页面传递无边界约束。
- 允许调用方提供锚点构建器和按场景设置菜单宽度，但不允许页面重新定义弹层机制。

通用组件不读取 Provider、不执行异步业务、不保存业务选择。选择回调只返回类型安全的
动作值，由调用方决定业务行为。

### 5.2 `AppLanguageSelector`

语言选择器负责：

- 从调用方接收当前 Locale、候选 Locale 和选择回调。
- 通过 `appLanguageSelfName` 显示每种语言的本族语名称。
- 把当前语言标记为选中，并使用勾选图标和 `selected` 语义表达状态。
- 使用整行设置卡片作为锚点，显示语言图标、字段标签、当前语言和展开箭头。
- 菜单宽度跟随设置卡片可用宽度，最大高度固定为 320px，超出后内部滚动。
- 先关闭菜单，再调用 Locale 变更回调，避免根 `MaterialApp` 重建期间残留旧语言弹层。

设置页只负责把 `selectableAppLocales`、当前 Locale 和
`globalAppProvider.notifier.setLocale` 连接到组件，不维护语言数量或菜单展示状态。

## 6. 交互与无障碍

- 三点按钮和语言选择行的有效交互尺寸不得小于 48×48 logical pixels。
- 三点按钮保留来自 ARB 的具体语义标签和 Tooltip；装饰图标排除重复语义。
- 语言选择行声明为按钮，并向屏幕阅读器提供“语言设置 + 当前语言”信息。
- `MenuItemButton` 负责标准菜单角色、焦点移动和 Enter/Space 激活；当前语言额外声明
  `selected` 状态。
- Escape 或点击菜单外部只关闭菜单，不触发动作；关闭后焦点回到锚点。
- 禁用项仍可见并保留禁用语义，但不能触发回调。
- 文本允许系统字体缩放，菜单项不得使用会裁剪文字的固定文本高度。

## 7. 性能边界

- 打开菜单不得创建 Navigator Route，也不得运行展开、缩放或淡入动画。
- 菜单构建不得读取高频 Provider、执行 IO、解析数据或启动异步任务。
- 打开三点菜单只允许更新对应 `MenuAnchor` 的 Overlay，不得触发列表页或整个应用卡片
  列表的业务状态变化。
- Profile 模式重复打开和关闭菜单时，以“输入后的下一帧可见、无持续 build/raster
  超预算帧”为验收目标。60Hz 环境下单帧预算为 16.7ms，具体结果以 Linux Profile
  时间线为准，不能用 Widget 测试的虚拟时钟冒充性能结论。
- 当前语言数量只有个位到低两位数，直接构建菜单项比维护自定义懒加载弹层更简单可控；
  若未来数量显著增长，搜索和虚拟列表只在 `AppLanguageSelector` 内演进。

## 8. 迁移范围

本次必须迁移以下旧菜单，完成后 Production 代码不再依赖路由式按钮菜单：

1. 更新应用行的“忽略此应用更新”。
2. 通用 `AppCard` 的页面注入动作。
3. 玲珑仓库管理的编辑、默认、优先级、镜像和删除动作。

现有回调、动作枚举、禁用条件和文案语义保持不变。本次不重构这些入口背后的业务流程。

## 9. 验证策略

测试只覆盖真实回归风险：

- 公共菜单：点击锚点后立即出现、选择前关闭、禁用项不可触发、选中语义正确。
- 设置页：初始只展示当前语言而非平铺全部语言；打开菜单后完整展示候选语言；选择后更新
  Locale 并关闭菜单。
- 更新页：活跃更新任务下“忽略”动作保持禁用，测试不再等待 300ms 动画。

同时执行 `flutter analyze`、相关 Widget 测试和 Linux 本地构建。无需为 Material SDK
已经保证的弹层定位和键盘算法复制单元测试，也不创建无法衡量真实帧耗时的伪性能测试。

## 10. 后续维护约定

1. 新增紧邻按钮或字段展开的轻量菜单时必须复用 `AppAnchoredMenu<T>`，禁止重新引入
   路由式按钮菜单、`showMenu` 或页面私有 Overlay。
2. Linux 原生菜单仅用于右键上下文场景；普通按钮菜单不得为了“原生感”跨平台通道。
3. 新增语言只按 `docs/38-arb-driven-linux-metadata.md` 的 ARB 流程操作；设置页会自动
   出现新语言，禁止增加语言白名单或单独修改语言选择器。
4. 菜单需要新能力时优先扩展结构化菜单项模型，禁止在调用页面复制样式和焦点逻辑。
5. 只有 Profile 证据证明公共实现无法满足帧预算时，才允许评估自定义 Overlay 或懒构建。
