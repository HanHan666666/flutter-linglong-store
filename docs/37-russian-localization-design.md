# 俄语本地化与跨层文案边界设计

> 文档版本：1.0  
> 更新日期：2026-07-31  
> 适用范围：Flutter 界面、系统通知、Linux 窗口标题、XDG Desktop Entry、AppStream 元数据

## 背景

项目当前通过 Flutter `gen-l10n` 维护中文、英文和西班牙语资源，并允许用户在设置页切换语言。本次增加俄语支持，目标不是只让俄语 ARB 通过编译，而是让用户从桌面启动器进入应用、浏览界面、执行安装与更新、查看系统通知时都获得一致的俄语体验。

现有实现存在以下维护问题：

1. 设置页手工声明中文、英文和西班牙语选项，新增语言必须同步修改多个列表和辅助方法。
2. 持久化语言值未经支持列表校验，历史或损坏值可能让全局状态与 Flutter 实际回退语言不一致。
3. `MaterialApp` 与原生 Linux 窗口标题固定为中文，语言切换不能完整反映到桌面窗口。
4. 玲珑环境管理等较新的功能仍在 Presentation、Application 或 Domain 中保存中文展示文案。
5. Desktop Entry 和 AppStream 只包含默认文案与中文文案，俄语桌面环境无法得到本地化名称、摘要和搜索关键词。
6. 俄语具有 `one/few/many/other` 数量变化，仅替换 `{count}` 无法保证语法正确。

## 目标

- 为所有现有 ARB 资源提供完整俄语翻译。
- 用户首次启动时可以按受支持的系统语言选择界面；已有显式选择始终优先。
- 设置页从生成的支持语言列表构建选项，不再手工维护语言数量。
- 业务和领域层只传播稳定代码、结构化事实与原始诊断，用户文案在 Presentation 本地化。
- 应用窗口标题和更新批次系统通知跟随当前语言。
- Debian、Ubuntu、Fedora、deepin 及其他遵循 freedesktop 规范的桌面环境可以读取俄语桌面元数据。
- 新增语言时，资源缺失和占位符漂移能在验证阶段被发现。

## 非目标

- 不为后端新增俄语数据或修改后端接口。
- 不翻译应用名称、应用简介、标签等后端内容。
- 不翻译 `ll-cli`、systemd、HTTP 或特权脚本返回的原始诊断文本。
- 不引入运行时语言包、第三方翻译框架或网络翻译服务。
- 不改变 application ID、desktop ID、XDG 数据目录或系统通知身份。
- 不为本次功能编写与真实风险无关的测试。

## 方案选择

### 方案一：只新增俄语 ARB

新增 `app_ru.arb`、设置页俄语选项和生成文件。

优点是改动小；缺点是窗口标题、环境管理、桌面菜单和 AppStream 仍会出现中文。这种方案把语言清单继续分散在多处，下一次新增语言仍需重复修改。

### 方案二：复用 Flutter ARB，并收敛本地化边界

保留 Flutter 官方 ARB 与 `gen-l10n` 生成链，让 ARB 文件集合成为支持语言的事实来源；设置页、持久化恢复、窗口标题和系统通知都消费同一生成结果。同时把跨层自然语言改为稳定代码和结构化事实，并补齐 XDG 元数据。

本项目采用方案二。它不引入新的国际化框架，并能消除现有分散配置和跨层中文文案。

## 总体架构

```text
app_*.arb
   │
   ├── flutter gen-l10n ──> AppLocalizations + supportedLocales
   │                              │
   │                              ├── 设置页语言选项
   │                              ├── Flutter 界面与无障碍文案
   │                              ├── 窗口标题
   │                              └── 更新批次系统通知
   │
Domain / Application ──> 稳定代码 + 结构化事实 + 原始诊断
                                      │
                                      └── Presentation 映射为 AppLocalizations

打包渲染配置 ──> Desktop Entry[ru] + AppStream xml:lang="ru"
```

Flutter 运行时资源与 Linux 原生桌面元数据属于两个消费阶段：前者在应用进程中生成和解析，后者必须在安装包构建阶段写入标准文件。因此两者共享术语和产品名称，但不强行把 ARB 解析逻辑塞进 Shell 打包脚本。

## 语言资源设计

### Locale 标识

俄语使用通用语言标识 `ru`：

- Flutter：`Locale('ru')`
- ARB：`"@@locale": "ru"`
- Desktop Entry：`Name[ru]` 等本地化键
- AppStream：`xml:lang="ru"`

当前产品不区分俄罗斯、白俄罗斯等区域变体，因此不声明 `ru_RU`。语言级 `ru` 可以覆盖通用俄语桌面环境，也避免以后增加区域变体时出现重复资源。

### 语言自身名称

所有 ARB 增加 `languageSelfName`：

| Locale | 值 |
| --- | --- |
| `zh` | `中文` |
| `en` | `English` |
| `es` | `Español` |
| `ru` | `Русский` |

设置页遍历 `AppLocalizations.supportedLocales`，通过每个 Locale 对应的 `AppLocalizations` 读取自身名称。这样新增 ARB 后会自动出现语言选项，不再维护单独的语言列表和名称 Map。

### 资源完整性

俄语文件必须覆盖中文模板中的全部业务键，并保持以下内容一致：

- 资源键集合；
- `@key` 元数据；
- 占位符名称；
- 占位符类型；
- plural/select 所需的数值占位符。

生成文件属于参与编译的源码，必须与 ARB 一起提交，禁止手工编辑。

### 俄语复数

所有 `int/num` 数量文案按语义使用 ICU plural。俄语至少覆盖：

- `one`：以 1 结尾但不以 11 结尾；
- `few`：以 2 至 4 结尾但不以 12 至 14 结尾；
- `many`：其余大多数整数；
- `other`：非整数或兜底。

后端传入且当前建模为 `String` 的数量不强行参与 plural；这类文案使用不依赖名词词形的表达，避免先解析后端展示值造成精度或格式损失。

### 术语约定

- 产品品牌统一写作 `Linyaps`，不翻译品牌名。
- `ll-cli`、systemd、App ID、desktop ID、仓库 URL 和文件路径保持原样。
- 用户界面的“仓库”翻译为 `репозиторий`。
- 原始命令输出和后端诊断保持原文，并与本地化解释文案分区展示。

## Locale 状态与首次启动

### 单一解析入口

新增通用 Locale 解析能力，负责：

- 根据 language code 查找生成器声明的支持语言；
- 兼容 `ru_RU`、`ru-RU` 等输入并归一为 `ru`；
- 对未知语言返回明确的默认 Locale；
- 为无 BuildContext 的系统通知和窗口标题加载对应资源。

侧边栏不得继续维护独立的语言归一逻辑，应复用这一入口。

### 优先级

应用启动时按以下顺序解析语言：

1. SharedPreferences 中存在合法的用户选择时使用该选择；
2. 没有用户选择时，从系统首选 Locale 中查找第一个受支持语言；
3. 没有匹配项时回退中文。

用户主动选择后只持久化规范化 language code。非法 Locale 不允许写入状态或持久化文件。

### 后端语言边界

应用内容接口当前只约定 `zh_CN/en_US`，本次不扩大后端契约：

- `resolveApiLang` 保持现有行为；
- 俄语界面下的后端内容继续使用现有回退结果；
- 错误解决方案查询继续传当前语言代码 `ru`，后端未命中时沿用现有“暂无解决方案”交互。

后端以后支持俄语时，只修改后端语言契约和 API Locale 映射，不需要改动客户端界面资源。

## 跨层本地化边界

### Domain

Domain 不保存面向用户的自然语言。环境问题模型只保留：

- 问题代码；
- 严重级别；
- 修复动作；
- 原始诊断；
- 渲染文案所需的结构化事实。

### Application

Application 负责编排、状态变化和错误分类，不读取 `BuildContext`，也不生成俄语、中文或英文文案。可预期结果使用稳定结果代码；不可控外部失败保存原始诊断。

### Presentation

Presentation 是用户文案的唯一解析层：

- 根据稳定代码选择 ARB 资源；
- 把路径、应用名、使用率、数量等事实传入占位符；
- 保持原始诊断可复制，不修改诊断内容；
- 所有无障碍标签继续使用同一套 ARB。

本次优先清理直接影响俄语完整性的用户可见硬编码，重点覆盖玲珑环境管理、下载管理概览、设置入口、空状态和窗口标题。日志、测试描述、开发注释不属于本地化资源。

## 应用标题与系统通知

### Flutter 标题

`MaterialApp.router` 使用 `onGenerateTitle` 读取 `AppLocalizations.appTitle`，禁止继续声明固定中文 `title`。

### Linux 原生窗口标题

窗口管理器初始化阶段可以使用默认标题，但在读取持久化配置后、窗口显示前必须设置正确语言标题；运行期语言切换后同步更新原生标题。标题同步是平台副作用，应由集中组件或服务处理，不散落到设置页。

### 更新批次通知

批次通知继续通过 `SystemNotificationGateway` 发送。通知策略根据批次保存的 Locale 或当前规范化 Locale 加载 `AppLocalizations`，俄语只增加资源，不增加平台判断或俄语专用通知逻辑。

通知失败仍不得改变更新任务结果。

## Linux/XDG 桌面元数据

### Desktop Entry

canonical desktop template 和隐藏兼容入口增加俄语 `Name` 与 `Comment`。canonical 入口另外增加：

- `GenericName[ru]`
- `Keywords[ru]`

默认无后缀键继续保留，满足 Desktop Entry 对本地化键必须存在默认值的要求。`Keywords[ru]` 保持分号分隔和结尾分号。

### AppStream

AppStream 元数据增加俄语：

- `<name xml:lang="ru">`
- `<summary xml:lang="ru">`
- `<p xml:lang="ru">`

Stable 与 Nightly 的名称和摘要仍由公共渲染脚本产生，所有 Deb、RPM、AppImage 和 AUR 路径消费相同结果，禁止分别维护俄语副本。

### 字体

项目使用 Flutter 默认系统字体与既有 fallback，不捆绑新的俄文字体。主流 Linux 发行版默认字体均覆盖西里尔字母；这可以避免增加包体积和字体许可维护成本。

## 性能约束

- ARB 仍采用编译期生成，不在运行时解析 JSON。
- 设置页语言列表规模很小，按打开页面时解析，不增加常驻监听。
- 页面继续只监听当前 Locale，不增加每个 Widget 的独立 Provider。
- 原生窗口标题只在启动和 Locale 变化时更新。
- 系统通知按批次完成事件生成一次，不增加轮询或 Shell 进程。

## 验证策略

只覆盖本次功能的真实风险：

1. ARB 键、元数据和占位符完整性检查。
2. `flutter gen-l10n` 生成与 Git 基线一致。
3. 现有设置页和国际化测试增加俄语支持、选择和持久化场景。
4. 现有本地侧边栏测试增加俄语标签。
5. 数量敏感的俄语文案检查 `1/2/5/11/21` 等代表值。
6. 更新批次通知检查俄语标题、汇总和应用名。
7. Desktop Entry 检查 `Name[ru]/GenericName[ru]/Comment[ru]/Keywords[ru]`。
8. AppStream 运行格式验证，并检查俄语 Stable/Nightly 渲染值。
9. `flutter analyze`、全量 `flutter test`、Linux release 构建和现有打包 smoke test。

不为简单 getter、常量或生成文件编写无业务价值的单元测试。

## 提交拆分

1. `docs: 补充俄语本地化设计`
2. `refactor: 统一客户端本地化边界`
3. `feat: 添加俄语界面支持`
4. `build: 添加俄语桌面元数据`
5. 必要的独立测试或维护文档提交

每个提交必须保持可构建或明确只包含设计文档；最终验证通过后推送当前分支。

## 长期维护规则

1. 新增语言只通过 ARB 文件声明，设置页不得增加手工语言分支。
2. 业务层不得保存本地化后的任务状态、结果或错误文案。
3. 原始诊断与本地化解释必须分离，禁止为了翻译而改写 `ll-cli` 输出。
4. 所有参与编译的生成本地化文件必须提交。
5. 新增用户可见文案时同步更新全部受支持 ARB；验证不得依赖 Flutter 的运行时回退掩盖缺失翻译。
6. Linux 桌面可见产品文案变更时，同步维护 Desktop Entry 与 AppStream，并运行公共打包渲染验证。
