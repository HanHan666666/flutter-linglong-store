# 55 - 下载管理依赖处理步骤设计

> 状态：已实施并通过自动化验证，待 Omarchy 真机回归
>
> 日期：2026-09-27
>
> 关联：[issue #25 的依赖进度建议](https://github.com/HanHan666666/flutter-linglong-store/issues/25#issuecomment-5548651568)、docs/07、docs/34、docs/54

## 1. 背景与协议事实

下载管理器当前只展示父应用的单项进度。`ll-cli --json` 的安装输出包含
`message` 和一个整个任务的 `percentage`；处理包时，`message` 可能形如
`Installing main:org.deepin.runtime.dtk/25.2.2/x86_64/binary [35.31KB/s]`。
这能辨认当前处理的包，但不能可靠得知依赖总数、每个依赖的独立百分比、尚未开始的
依赖或单项完成事件。更新任务的 `Updating <ref>/<module>` 同理。

因此界面只能呈现 **实际观察到的处理步骤**：当前处理哪个依赖、此前处理过哪些依赖。
原百分比继续表示父应用的整个安装/更新任务，绝不能换算或重复显示成依赖百分比。

## 2. 方案比较与决定

1. **查询依赖清单并估算逐项百分比**：需要额外 CLI/平台调用，且无法与安装时实际
   解析结果及全局传输字节数稳定对应；拒绝。
2. **仅保留现有单行 `message`**：无状态改动，但上一项依赖一旦切换就消失；不能
   满足“当前/以前处理过什么”；拒绝。
3. **解析现有流并记录已观察到的依赖**：不增加系统调用，不改变安装顺序；采用。

## 3. 分层与状态

- Data 只从 `ll-cli --json` 的非错误事件中严格匹配 `Installing/Updating
  [channel:]appId/version/arch/module`，提取包 ID；不从普通日志、错误文本或
  非完整 ref 猜测。原始日志照旧保存。解析在输出到达时做一次，不在 Flutter
  `build` 中扫描日志。
- Domain 的 `InstallProgress` 携带本行处理包 ID；`InstallTask` 持有顺序去重的
  `observedDependencyIds` 和可空 `activeDependencyId`。Freezed/JSON 使用默认空值，
  旧队列快照可直接读取。两字段只是观察事实，不表示已安装清单。
- Application 的队列 reducer 是唯一归并入口。提取 ID 与父 `appId` 不同时，
  才加入观察列表并设为当前；新依赖出现时，上一项转为“此前处理”。再次出现的
  ID 不重复添加。遇到父应用包 ID、明确的其它阶段、终态时清除当前标记，保留已
  观察列表；未识别消息不擅自改变当前身份。高频同一 ID 消息不得反复扩容列表。
- Presentation 仅在当前父任务主卡片下显示依赖区域，无依赖时完全隐藏；按观察
  顺序用 builder 展示 ID，当前项标为“正在处理”，其余标为“此前处理”。
  一条父任务仍只有一根全局进度条、一组取消/重试动作和一个概览计数。任务离开
  当前区域后不再展示步骤，历史任务的观察事实可用于日后诊断。

## 4. 边界与性能

- 不推断完整依赖树，不标记单项“下载完成”或“安装成功”，不显示单项百分比/剩余
  时间，不把依赖纳入独立队列，不为依赖新增取消或重试。
- `ll-cli` 版本若改变消息格式、只报告父应用或没有依赖消息，区域保持隐藏；安装
  业务不受影响。坏格式和错误事件不能污染观察列表。
- 任务状态与持久化仍以 `InstallTask` 为唯一事实来源；恢复中断任务不会凭观察列表
  继续安装。展示使用现有卡片尺寸/主题与方向感知布局，不额外订阅全局 Provider。

## 5. 验收

1. 解析：真实 `Installing/Updating` 示例能取出包 ID；泛化文案、坏 ref、错误
   事件和非 JSON 日志不能取出。
2. 归并：A→B→B→父应用/终态时，列表只含 A、B 且当前标记正确；父应用自身
   不能被显示为依赖；JSON round-trip 与旧快照缺省字段正确。
3. Widget：当前依赖、此前处理、整体百分比同时可见；无依赖时无占位；依赖不
   增加任务数、进度条或独立操作。
4. `flutter analyze`、定向测试、方向布局门禁和全量测试通过；Omarchy 上连续
   两任务及多依赖真机回归另行进行。

## 6. 验证结果

- 解析、Repository 传递、reducer 归并、旧快照兼容和卡片 Widget 的定向测试通过。
- `flutter analyze` 无问题；`build/scripts/verify_directional_layout.dart` 通过；
  `flutter test` 全量通过。执行全量测试时需要 Flutter SDK 的 `bin` 在 `PATH`，
  因为现有 helper 测试会启动 `dart` 子进程。
- 不具备 Omarchy 真机安装场景；多依赖显示以及 docs/54 的连续任务回归仍需用户
  在该系统确认。
