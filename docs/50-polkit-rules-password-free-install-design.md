# 50 - 设置页安装免密开关设计

> 日期：2026-09-09
> 状态：设计已修订，功能未实施
> 关联：`docs/47-pkexec-auth-popup-analysis.md`、`docs/23-install-cancel-sigterm-plan.md`
> 本次确定：本地缓存开关状态；用户切换时先提权读取系统状态，再按点击的目标值修改。

## 1. 需求与实施范围

在设置页增加「安装时免密码确认」开关，默认关闭。用户开启后，通过系统 polkit
规则让玲珑安装、更新及终端本地文件安装免密，减少安装过程中的授权打断。
开启前说明影响并确认；开启、关闭设置本身都需要系统授权。

本功能包含三项必要改动：

1. 设置页开关、开启确认、本地状态缓存，以及切换时的提权同步。
2. 安装类 action 的固定 polkit 规则，以及规则的安全写入、删除和结果回读。
3. 商店统一安装入口的执行路径选择：开启时以普通用户执行 `ll-cli`，关闭时沿用
   docs/47 的特权 helper；队列、进度解析、结果复验和完成后刷新继续复用。

不增加商店本地文件安装页面，不修改上游 policy，不新增自定义 polkit action，
不开放通用 `pkexec`、Shell 或任意程序免密。商店自更新、环境修复、卸载、手动清理、
仓库配置均继续使用各自现有流程。

## 2. 现状与方案选择

### 2.1 已核实的现状

- 生产组合根 `lib/bootstrap/production_dependency_overrides.dart` 为 CLI Repository
  注入应用级 `PrivilegedHelperClient`。安装、更新首次启动 helper 需要 pkexec 授权，
  helper 存活期间复用会话。
- 当前生产链路遇到 helper 不可用时会失败并暂停自动消费，不会自动回退普通 CLI。
- Repository 已保留普通 `ll-cli` 流式执行能力，但取消分支仍按 helper 是否注入选择；
  不能仅在开启时绕过 helper 启动，而遗漏取消路由。
- 上游安装授权的 action 是 `org.deepin.linglong.PackageManager1.*`，与启动 helper
  使用的 `org.freedesktop.policykit.exec` 是不同的授权边界。
- 本机 `/etc/polkit-1/rules.d` 为 `0750 root:polkitd`，普通用户无法遍历。
  不能把普通用户的文件存在性检查作为开关状态来源。

### 2.2 方案决策

| 方案 | 改动与效果 | 决策 |
|---|---|---|
| 只写规则，商店始终走 helper | 终端 CLI 可免密，商店启动 helper 仍需要授权 | 不采用，设置应影响商店自己的安装体验 |
| 写规则，开启时走普通 CLI、关闭时走 helper | 复用两条已有执行能力；补齐统一选择、任务取消和异常映射 | 采用 |
| 给通用 pkexec、bash 或用户目录中的 helper 添加免密规则 | 扩大提权范围，且 AppImage/解压目录中的文件可由普通用户替换 | 不采用 |

这是用户主动选择的安装模式，不是 helper 失败后的隐式降级。
本文件补充 docs/47 的默认链路约定：**开关关闭时仍完整遵循 docs/47；开启时允许在
同一 Repository 内选择普通 CLI。任何一次任务失败都不自动切换执行路径重试。**

## 3. polkit 规则与适用范围

### 3.1 固定路径和加载顺序

- 文件：`/etc/polkit-1/rules.d/60-linglong-store.rules`。
- 属主与权限：`root:root`、`0644`，必须是普通文件。
- 不调整 `rules.d` 的权限，不要求用户加入 `polkitd` 组。
- 文件名前缀沿用 `60-`，用于稳定命名，不表示它能覆盖所有发行版或管理员策略。

polkit 按文件名字典序注册规则，并按注册顺序求值；**首个返回有效授权结果的规则
决定结果**。因此早于本文件的规则可能先行决定授权，而本规则命中后，后面的规则
不会再处理该请求。管理员需要优先限制本功能时，应使用排序早于本文件的规则。
禁止为了绕过管理员策略而自动改名、挪动或重写其他规则。

polkitd 监听规则目录并自动重新加载，无需重启服务或注销。重新加载是异步的；
规则文件保存状态与某次请求的有效授权结果分别由文件回读和 polkit 决策确定。

### 3.2 固定规则正文

```js
/**
 * 玲珑商店安装免密规则，模板版本 1。
 * 仅为本机活动会话放行安装类操作；其他操作继续由系统策略决定。
 * 此标记用于识别用途，文件归属判断仍须校验完整模板及文件元数据。
 */
polkit.addRule(function(action, subject) {
    // 会话限制用于缩小授权范围，不将远程或非活动会话纳入本规则。
    if (!subject.local || !subject.active) {
        return;
    }

    // 精确枚举 action，防止上游新增敏感操作后被前缀规则意外放行。
    if (action.id === "org.deepin.linglong.PackageManager1.install" ||
        action.id === "org.deepin.linglong.PackageManager1.update" ||
        action.id === "org.deepin.linglong.PackageManager1.install-from-file") {
        return polkit.Result.YES;
    }
});
```

实现时正文只维护一份模板常量；生成脚本、回读比对和测试均使用它。
必须使用大写 `polkit.Result.YES`；小写 `.yes` 是 `undefined`，不会产生免密授权。
测试须验证求值结果，不能只验证模板字符串没有变化。

### 3.3 操作划分

| action | 本规则处理 | 业务含义 |
|---|---|---|
| `install` | 本机活动会话返回 `YES` | 安装应用，可能包含依赖安装、版本替换 |
| `update` | 本机活动会话返回 `YES` | 更新应用，可能包含旧版本和关联内容的自动清理 |
| `install-from-file` | 本机活动会话返回 `YES` | 终端等现有入口安装 `.layer`/`.uab`，可能替换已有版本 |
| `uninstall` | 不处理 | 独立卸载操作继续走原授权流程 |
| `prune` | 不处理 | 独立手动清理操作继续走原授权流程 |
| `set-configuration` | 不处理 | 修改 daemon 配置继续走原授权流程 |
| `org.freedesktop.policykit.exec` | 不处理 | 启停设置所用的特权脚本、helper 及其他提权操作不获得免密 |

CLI 的更新命令沿用项目现有 `ll-cli upgrade`；`update` 是 polkit action 的末段，
不能据此拼接不存在的 CLI 子命令。

### 3.4 删除与替换风险的处理办法

本功能采取「只豁免安装类 action」的边界，明确保留独立卸载、手动清理和修改配置
的原授权流程。对这些 action 返回“不处理”，不额外添加 `NO` 或 `AUTH_ADMIN`，
以免改变其他管理员规则、发行版默认值或已有授权缓存。

安装与更新本身会改变已有软件。上游本地安装支持版本替换，安装完成后也可能自动
清理旧版本和依赖；这些行为属于安装事务，不一定另发 `uninstall` 或 `prune` 授权。
因此本方案不把「卸载 action 未放行」描述成「已有软件不会被替换或删除」。

具体处理：

1. 规则严格保留上述白名单，不开放独立卸载、清理、配置操作。
2. 开启确认明确说明：其他本机程序也可能免密安装或替换应用，更新可能清理旧内容。
3. 正常安装、更新保留上游事务语义，不用商店弹窗或隐藏 CLI 参数冒充系统限制。
4. 如果以后需要禁止一切替换、降级或关联删除，必须另行设计上游参数级授权或
   守护进程限制；仅凭当前三个 action 无法区分这些行为，不纳入本功能。

## 4. 开关状态：本地缓存，切换时提权同步

### 4.1 本地缓存

复用组合根已注入的 `SharedPreferences`，不新建数据库、系统状态服务或后台轮询。
使用单个键 `setting_password_free_install_state` 保存一个版本化 JSON：

```json
{"version":1,"enabled":false,"needsSync":false}
```

| 字段 | 含义 |
|---|---|
| `version` | 缓存格式版本，当前为 1 |
| `enabled` | 最近一次由特权操作确认的本功能配置；没有缓存时显示关闭 |
| `needsSync` | 上一次修改尚未获得可靠结果，或结果未能完整写回缓存，需要下次操作同步 |

单个键避免把 `enabled` 和 `needsSync` 分开写入造成逻辑上的半更新；仍须检查
SharedPreferences 写入结果。缓存缺失使用默认关闭，缓存损坏/版本不支持时使用
关闭显示并提示状态待同步，不据此创建、删除任何系统文件。

设置页首帧从已初始化的内存偏好恢复状态，不访问受限目录，不调用 pkexec，
不执行同步文件 IO。普通刷新、页面切换、启动应用均不为读取开关弹授权框。

缓存用于界面展示和下一次安装的执行路径选择，**不授予系统权限**。管理员手动修改
规则、其他用户切换开关或清空本地数据都可能使缓存过期；这是采用本地缓存后的明确
行为，用户下一次主动切换时通过 root 回读校正。

### 4.2 root 读取的系统状态

特权侧只检查本功能的固定路径，返回以下状态：

| 状态 | 判定 | 处理 |
|---|---|---|
| `enabled` | 普通文件、root:root、0644，内容与受支持模板逐字节一致 | 可认定本功能规则已配置 |
| `disabled` | 固定路径不存在，且不是悬空符号链接 | 可认定本功能规则未配置 |
| `conflict` | 同名文件内容不同、符号链接、目录、属主或权限异常 | 不覆盖、不删除，提示规则冲突 |
| `unknown` | 无法可靠读取或命令输出不完整 | 保留最近显示值并标记待同步 |

当前只支持模板版本 1。将来升级模板时必须显式列出可迁移的历史模板，不能仅凭
一行“由商店生成”的注释覆盖用户文件。`disabled` 仅表示本功能文件不存在，其他
管理员规则仍可能使同类操作免密；不扫描或删除其他来源的规则。

### 4.3 用户切换时的事务

开关点击产生明确目标 `desiredEnabled`。目标在点击时固定，不能提权后再对系统
真实状态取反，否则本地缓存过期时会执行与用户点击相反的操作。

一次用户操作的顺序：

1. 控制器取得单飞锁。开启时先显示风险确认，用户取消则不调用系统命令。
2. 确认后暂缓新安装任务出队，进行中的任务继续执行；保留当前缓存快照，将
   `needsSync=true` 写入缓存，写入失败则不启动修改。
3. 启动一次特权脚本，获得 root 权限。
4. 在同一 root 进程内取得跨实例锁，**先读取真实状态**。
5. 若真实状态已等于目标，直接返回，不重复写入或删除；不同则按目标操作。
6. 操作后仍在同一 root 进程内回读真实状态，输出结构化结果，再释放锁并退出。
7. GUI 根据回读值更新内存及本地缓存；已确定状态时清除 `needsSync`，展示结果。
8. 所有结束路径释放本次临时出队暂停；安装队列原有的授权失败门闩保持独立，
   不能因设置操作结束而自动解除。

读取、修改、回读共用这一次授权，不拆成两次 pkexec。示例：缓存显示关闭、系统
实际开启时，用户点击开启，root 读取后直接同步为开启，不把系统反转成关闭。

用户取消系统授权时，本功能尚未修改规则：恢复操作前缓存快照，提示「未完成授权，
未修改设置」。操作前已经待同步的状态不能因此被清除。读取到冲突或无法确定最终
状态时，不覆盖 `enabled` 的最近可靠值，保持 `needsSync=true` 并显示对应提示。

### 4.4 中断、缓存写入失败与多用户

- root 已完成修改但客户端崩溃或未收到完整结果：下次启动保留缓存显示并提示待同步；
  下次切换按 §4.3 先回读，再执行目标值，不根据旧缓存回滚系统。
- 修改失败但 root 回读成功：以回读状态更新缓存，同时说明此次目标未完成。
- 系统修改成功、缓存保存失败：当前界面显示已确认的系统值，并提示本地状态未保存；
  不把系统成功说成关闭，也不为修复缓存再弹授权框。提前写入的待同步标记用于恢复。
- 系统文件是全机配置，本地缓存按用户保存。另一用户或另一发布渠道的缓存不会自动
  更新；同一路径的特权修改须串行，最终结果以最近一次完成的系统操作为准。
- 本功能不监听受限目录，不为多用户同步新增后台服务。

## 5. 设置页交互与文案

### 5.1 入口

位置为 `setting_page.dart` 的 `_buildStoreOptionsSection`，复用现有
`SwitchListTile`、分隔线和 `ConfirmDialog`。只增加一个开关，不新增安全模式选择器。

- 标题：**安装时免密码确认**。
- 副标题：**安装和更新应用时免输密码；卸载等操作沿用系统授权设置。**
- 待同步时补充：**显示的是上次保存的状态，修改时将同步系统设置。**

开启确认正文：

> 开启后，本机活动登录用户可免密码安装、更新玲珑应用，终端和其他程序也会生效。
> 来路不明的程序可能在您不知情时安装或替换应用；更新还可能清理旧版本及关联内容。
> 单独卸载、手动清理和修改系统配置仍按系统原有授权设置处理。
> 这项设置对整台电脑生效，卸载商店后也会保留；如不再需要，请先在这里关闭。

- 标题：`开启免密码确认？`
- 确认：`我已了解风险，开启`
- 取消：`保持原设置`

关闭无需再次风险确认，直接进入系统授权与同步流程。成功文案为「已开启安装免密」
或「已关闭本功能的免密设置」；系统授权窗口由 polkit 展示，不模拟密码输入框。

### 5.2 状态机与性能

```text
ready → confirming（仅开启）→ applying（授权、同步与修改）→ ready
             └─取消───────→ ready
                              └─失败────→ ready + 错误/待同步提示
```

状态包含 `phase`、`enabled`、`needsSync`、结构化 `lastError`。
单飞约束从确认阶段开始，覆盖授权、修改、回读和缓存保存，防止重复确认框和重复提权。

- 非 `ready` 状态禁用开关；授权及处理阶段显示 loading，回调结束及时恢复。
- 控制器与操作生命周期不依赖设置页是否可见；离开页面后仍正确收尾并更新缓存。
- Presentation 不执行文件、进程或偏好写入，不保存第二份业务开关状态。
- 普通进入页面只读取本地状态；没有定时器、轮询和额外展开动画。
- 保留键盘操作、至少 48px 交互高度、开关语义和焦点恢复；状态提示使用 l10n。
- 错误详情复用项目可复制、可聚焦和 Tooltip 展示规范，完整日志写入既有 XDG 日志。

## 6. 特权修改与原子写入

### 6.1 唯一配置入口

新增平台 Gateway，只有它可为本功能构造和执行特权脚本。Application 编排状态，
Presentation 只发送目标值。复用 `ShellCommandExecutor` 的流式输出和日志能力。

命令使用参数数组调用 `pkexec --disable-internal-agent /bin/bash <脚本绝对路径>
<enable|disable>`，不通过 `bash -c` 拼接用户输入。root 脚本只接受两个固定动作、
只操作固定规则路径，正文来自随应用分发的固定模板。

用户临时工作区使用随机私有目录（0700）和脚本（0700），异步完整写入后再执行；
不能复用只有时间戳、位于共享 `/tmp` 根目录的可预测脚本名。GUI 在命令退出后于
`finally` 清理临时工作区；启动失败和取消授权同样清理，不能在授权仍等待时删除脚本。

这是用户主动切换此设置的一次性授权入口，不复用已获得安装授权的 root helper
静默修改系统策略，不扩展 helper 的命令白名单。实现时同步维护 docs/47 和仓库入口
约定，说明这一配置入口与安装传输入口的各自职责。

### 6.2 root 侧事务步骤

1. 验证自身 root 身份、动作参数，以及规则目录为预期的系统目录；目录缺失或环境
   不支持 JS rules 时明确失败，不修改目录权限或自动部署 polkit。
2. 打开规则目录文件描述符，对该描述符使用 `flock` 排他锁，最多等待 10 秒。
   本功能各实例必须共用此锁；不创建普通用户可预占的锁文件。
3. 在锁内读取 §4.2 的系统状态，记录 `before`；冲突时结束，不覆盖同名文件。
4. 若需要开启，在同一目录通过 `mktemp` 创建随机临时文件，文件名不以 `.rules`
   结尾，避免 polkit 提前加载半成品。
5. 将完整模板写入临时文件，检查写入结果，设置 root:root、0644，并比对内容。
6. 通过同目录 `rename`（Shell 实现使用 `mv -T`）一次性发布到固定路径。
   替换前再次确认目标仍为允许操作的状态，避免误覆盖管理员更改。
7. 关闭时仅删除通过归属校验的固定文件；不存在则幂等成功，不清理其他规则。
8. 回读 `after`，输出结果。所有正常/可捕获异常路径删除本次临时文件并释放锁。

使用临时文件加原子替换的成本仅为一次小文件写入和重命名，避免直接截断正式文件。
原子性范围是单个规则文件的可见性；不增加数据库事务或复杂备份系统。
强制杀进程等无法执行清理的情况，可能留下不以 `.rules` 结尾的临时文件，不会被
polkit 加载；下次 root 操作仅清理由本功能命名、root 所有的普通临时文件。

跨实例锁只协调本功能实例，不能代替管理员工具的协作。发现外部修改或回读不符时
按冲突/失败反馈，不循环抢写，也不自动恢复操作前文件覆盖管理员的新内容。

### 6.3 结果和错误契约

stdout 只输出固定结构的最终结果，诊断日志写 stderr；GUI 严格解析版本、枚举和
字段，不从自由文本推断成功。结果至少包含 `version=1`、`requestedEnabled`、
`before`、`after` 和 `outcome`（`applied`、`unchanged`、`conflict`、`failed`）。
脚本内部错误统一映射为自身定义的非零退出码，不直接透传子命令的 126/127，避免
把实际执行错误误识别为 pkexec 授权取消。没有可靠最终结果时按待同步处理。

正常成功须同时满足：退出码为 0、结果完整、`after` 等于用户目标，且对应文件已通过
§4.2 校验。异常路径尽量在 root 进程退出前回读；只有回读成功才更新缓存事实。
单凭“文件存在”或单凭退出码均不能判定开启成功。

授权与执行总等待上限为 120 秒，无图形授权代理时明确失败，不启用终端认证代理。
超时或通道断开不能假定 root 操作已经停止或已经回滚：标记待同步，下一次操作经
相同锁取得最新状态。服务不得无界重试或自动再次调用 pkexec。

| 情况 | 缓存与反馈 |
|---|---|
| 确认框取消 | 无系统调用，无状态修改 |
| pkexec 126，未启动 root 操作 | 恢复之前的缓存与待同步标记，提示未完成授权 |
| pkexec 不存在、127 或启动失败 | 保留最近状态，说明授权组件/系统授权不可用 |
| root 读到的状态已经等于目标 | 同步缓存，按幂等成功结束 |
| 文件冲突、目录/运行环境不支持 | 不修改规则，提示具体原因，缓存标记待同步 |
| 写入/删除失败，回读成功 | 保存实际状态，提示目标未完成 |
| 超时、结果格式错误、回读失败 | 保留最近可靠值，标记待同步，不显示操作成功 |
| 系统成功、本地保存失败 | 当前显示真实值，提示本地状态未保存，不回滚系统 |

规则回读确认的是本功能配置；实际授权仍受 polkit 加载时机、会话属性和管理员
优先规则影响。不得因为一次授权结果不符合预期，就修改其他规则或放行更多 action。

## 7. 商店安装链路的接入

### 7.1 统一选择

在 `LinglongCliRepositoryImpl` 的统一安装/更新入口选择路径；生产组合根注入读取
开关内存状态的只读函数，Data 不反向导入 Application Provider。

| 下一次任务启动时的本地状态 | 执行路径 |
|---|---|
| `enabled=true` 且 `needsSync=false` | 普通用户的 `ll-cli install/upgrade --json` |
| 关闭、缓存异常或待同步 | docs/47 特权 helper |

只在任务开始时取一次快照，并把实际路径与该任务绑定。设置改变不会切换正在运行的
任务；下一次任务使用新状态。原有 helper 可以完成已经开始的任务，空闲后沿用既有
回收机制，不因切换开关强杀进程。

设置控制器通过 Application 层队列入口临时暂停新任务出队，确认取消不暂停；
从正式进入授权到结果收尾期间不启动新任务，避免一边同步系统规则一边启动另一轮
安装授权。暂停按事件释放，不轮询，不取消当前任务，也不覆盖原有授权失败门闩。

两条路径共用现有单任务队列、CLI 输出解析、超时策略、结果复验、完成后刷新和日志。
普通 CLI 路径不调用 `ensureStarted()`，也不额外用 pkexec 包装；由上游 daemon 的
polkit 检查决定安装是否获准。商店不新增 LinYAPS 私有 D-Bus 安装协议实现。

### 7.2 取消必须按实际任务路由

- helper 任务：继续通过既有 requestId 向 helper 请求取消。
- 普通 CLI 任务：保留该任务真实 `Process` 句柄，向自己启动的进程发 SIGTERM，
  由 CLI 的信号处理触发 `cancelCurrentTask → D-Bus Cancel`。
- 不根据当前开关值、helper 是否注入或 helper 是否仍存活来取消另一路任务。
- 普通 CLI 路径不复用旧 `cancelWithSystemKill` 的 `pkexec kill` 分支，避免取消
  再次授权；不使用 `killall`，不杀 daemon。
- 发出信号仅表示取消请求已发送，仍须等待进程/任务结果并遵循现有结果复验规则。
  信号失败、进程已退出或任务已完成时，不伪造 `cancelled`。

适配旧 CLI 时须核实它是否会自行提权并改变进程身份。若出现信号权限不足，返回
可诊断的取消失败，不暗中追加另一轮 pkexec。目标版本的普通用户安装与协作取消
必须一起通过真机测试，不能只沿用旧 root CLI 取消注释推断行为。

### 7.3 缓存过期和授权失败

不为每个安装任务额外启动 root 探测、`pkcheck` 或轮询进程，正常执行只增加一次
内存模式读取。缓存过期、规则尚未加载或优先规则要求认证时，真实 CLI 可能仍触发
系统授权；本地偏好不能绕过 daemon 的决定。

对确认属于安装授权取消/拒绝的结果，复用 `AppOperationFailure` 承载事实并暂停
队列自动消费，提示用户在设置中重新同步或关闭免密：

- 有明确用户取消事实时沿用 `authorizationCancelled`。
- 对明确的授权拒绝新增稳定类型 `authorizationDenied`，同步失败格式化、持久化
  生成物和队列门闩；不把它归为 helper 不可用或网络错误。
- 若上游只给出通用 `AccessDenied`，按授权拒绝处理，不猜测用户是否点击了取消。
  错误识别以目标版本的结构化错误及已核实的诊断契约为依据，不臆造 CLI 错误码。

不得失败后自动再走 helper 重试，也不继续批量任务形成连续授权框。
普通网络、仓库或下载失败不误归类为授权问题。

用户之后成功同步开关不自动重启失败任务，仍由用户明确重试/入队解除现有授权门闩。

## 10. 测试与验收

### 10.1 自动化覆盖

| 范围 | 必须覆盖的行为 |
|---|---|
| 规则求值 | 三个安装 action 在本机活动会话返回 `YES`；卸载/清理/配置/通用 exec 不处理；远程、非活动会话不处理；未知 action 不处理；前序拒绝规则优先 |
| 缓存 | 无缓存默认关闭；损坏缓存待同步；不读受限目录；页面进入不提权；修改中断后的标记恢复；保存失败反馈 |
| 状态同步 | 缓存与真实状态相反；目标与真实值已一致；先读取再修改；126 保留原缓存；完整操作仅一次提权；冲突不覆盖 |
| 原子写入 | 替换前失败保持原文件；不存在目标时失败不留下正式空文件；权限与模板回读；临时文件不被加载；删除幂等；同名 symlink/目录拒绝 |
| 事务边界 | 非 0 但可回读；0 但结果不完整；root 完成后 GUI 中断；锁等待超时；多个实例串行；临时目录清理 |
| 安装与取消 | 开启不启动 helper；关闭复用 helper；运行中切换不改变当前取消路径；普通 CLI 取消不调用 pkexec kill；取消信号失败不伪造成功 |
| 队列 | 设置事务暂缓新任务且所有结束路径释放；不打断当前任务；不解除原授权门闩；授权取消/拒绝后暂停自动消费；不自动换路径重试；普通下载错误不挂授权门闩 |
| Widget | 开关、开启确认、关闭流程、确认阶段防重入、loading、待同步提示、离页收尾、键盘和无障碍语义 |

规则测试使用与 polkit API 一致的求值环境，不把小写 `yes` 等错误在 mock 中补成合法
常量。root 脚本使用隔离目录和故障注入验证，不在自动化单测中修改开发机真实策略。
安装测试桩须保持真实 CLI 的退出、信号和授权错误语义，不能放宽替身掩盖边界缺陷。

### 10.2 真机验收

在目标 LinYAPS/polkit 版本及 DEB、RPM、AppImage 运行形态中核实：

1. 默认关闭进入设置页不弹授权；取消开启确认不触发系统操作。
2. 开启时完成一次系统授权，在同一特权操作内先读取后修改，回读与本地缓存一致。
3. 重启商店后首次安装、连续安装、批量更新使用普通 CLI，规则命中时不弹授权；
   取消安装同样不弹授权，任务和队列正确收尾。
4. 终端 `ll-cli install`、`ll-cli upgrade`、本地文件安装命中对应规则。
5. 独立卸载、手动清理、修改配置不由本规则放行；根据实际系统基线验证授权结果，
   不把已有授权缓存或管理员其他规则造成的免密误判为本功能扩大范围。
6. 关闭只移除本功能规则；后续商店任务恢复 helper 路径，正在运行的任务不切换。
7. 人工修改/移除规则后，页面仍按本地缓存展示；下一次切换通过提权回读正确同步。
8. 0750 规则目录、授权取消、无代理、文件冲突、磁盘写入失败和缓存失败均反馈明确。
9. SSH、非活动会话及早于本文件的拒绝规则不被本规则放行。

真机测试在用户明确允许修改系统策略的环境执行，并记录操作前规则和测试后恢复结果。
本设计文档修订不执行上述系统写入。

## 11. 生命周期与实施顺序

规则是系统配置，商店卸载不会自动清理。本次不增加卸载钩子，风险确认中已说明残留；
用户应在卸载前关闭。商店已卸载时，可由管理员确认文件为本功能规则后手动删除：

```bash
sudo rm -f /etc/polkit-1/rules.d/60-linglong-store.rules
```

删除仅撤销本功能对后续授权检查的影响，不中断已开始的安装，也不清除其他来源的
规则或既有授权会话。不重启 polkit，不停止 daemon，不强制退出商店。

实施按功能点分批提交，每批附对应测试，保持可分析和可构建：

1. `feat: 新增免密规则事务与本地状态同步`：Domain、平台 Gateway、服务、控制器、
   根部装配和相应单测。
2. `feat: 接入免密安装执行路径与任务取消`：统一 Repository 选择、实际任务路由、
   授权失败门闩和相应回归测试。
3. `feat: 设置页增加安装免密开关`：交互、10 语言文案、生成源码和 Widget 测试一起提交。
4. `docs: 补充免密安装验收记录与入口约定`：记录真实验证结果，同步 docs/47、架构和
   AGENTS.md 中与本功能直接相关的入口约束，不把待验证项目写成已通过。
