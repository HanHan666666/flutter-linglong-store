# OpenCode 风格壳层与主列表页视觉统一设计

> 日期：2026-07-04  
> 状态：方案已确认，等待文档审阅后进入实施计划  
> 适用阶段：第一阶段，先完成全站 Shell + 主列表页统一；第二阶段再扩展到详情页、设置页、下载管理和弹窗面板。

## 1. 背景

用户希望当前 Flutter 玲珑应用商店吸收 OpenCode 截图中的视觉风格，重点解决现界面灰色底过重、主内容区与侧边栏分块明显、底部滚动区域边界突兀、列表卡片之间灰色沟槽过强的问题。用户已确认采用“方案 B：壳层统一 + 主列表页轻量重排”。

现有项目已经有 `docs/03e-aurora-layer-linux-desktop-design-system.md`，其设计关键词是轻盈、干净、有层次但不过度玻璃、现代桌面感。当前实现仍保留较多旧版 Ant Design 迁移痕迹，例如 `surfaceContainerLow = #F5F5F5` 作为大面积内容底色，白色卡片叠在灰色底层上，导致视觉分层比规范目标更重。

本设计不另起一套 UI 体系，而是在 Aurora Layer 方向内吸收 OpenCode 的“统一白色画布、轻边框、内容区圆角、弱灰底、弱分隔”的桌面壳层语言。

## 2. 现状分析

### 2.1 相关架构入口

- `lib/presentation/widgets/app_shell.dart`：应用壳层，负责 `TitleBar + Sidebar + Content`。
- `lib/presentation/widgets/title_bar.dart`：自定义标题栏、全局搜索、窗口按钮。
- `lib/presentation/widgets/sidebar.dart`：一级导航、动态分类和底部入口。
- `lib/presentation/widgets/sidebar_interaction_surface.dart`：侧边栏 hover / active 交互表面。
- `lib/core/config/theme/app_colors.dart`、`app_theme.dart`、`app_spacing.dart`：颜色、主题、圆角与间距令牌。
- `lib/presentation/widgets/app_card.dart`、`responsive_app_grid.dart`：推荐、全部、搜索、排行等主列表页复用的卡片和网格。
- 主列表页包括 `RecommendPage`、`AllAppsPage`、`RankingPage`、`SearchListPage`、`MyAppsPage`、`UpdateAppPage`。

### 2.2 当前视觉问题

1. 主内容区使用明显灰底，滚动到底部时灰色底层与白色卡片形成强烈块状感。
2. 标题栏、侧边栏、内容区虽然都接近白色或浅灰，但缺少统一外层画布，视觉上像三个独立模块拼接。
3. 内容区左上圆角只有局部处理，底部没有同样轻的容器边界，导致用户截图中红框区域显得突兀。
4. 侧边栏选中态包含蓝色竖条、浅蓝背景和字重变化，和 OpenCode 的克制选中行相比更重。
5. 卡片自身较轻，但卡片之间透出的灰底过强，放大了网格间距。
6. 搜索框、分类栏、排行 Tab、我的应用搜索栏仍有不同层级的灰底表达，页面之间统一性不足。

## 3. 方案选择

已讨论三种方案：

| 方案 | 内容 | 取舍 |
| --- | --- | --- |
| A | 只调颜色令牌 | 改动小，但只能把灰底变浅，内容边界和列表节奏问题仍存在。 |
| B | 壳层统一 + 主列表页轻量重排 | 改动集中在 Shell、主题令牌和共享列表组件；业务逻辑不变；能优先解决最明显的观感问题。 |
| C | 直接全站重做 | 效果最完整，但会同时牵动详情页、设置页、下载管理和弹窗，回归面过大。 |

确认采用方案 B。第一阶段先解决全站入口和主列表页，第二阶段再扩展深层页面。

## 4. 设计目标

1. 接近 OpenCode 的轻桌面应用气质：白色主画布、极浅顶栏、极轻内容边框、内部圆角和弱 hover。
2. 降低灰底占比：灰色只承担 hover、输入底、弱分组背景，不再作为主内容的大面积底色。
3. 统一壳层：标题栏、侧边栏和内容区归入同一视觉容器，避免明显拼接感。
4. 保持高性能：不新增昂贵模糊、全屏阴影或滚动期重复计算；列表仍使用 builder / sliver。
5. 保持业务行为等价：不改接口、不改 Provider、不改安装队列、不新增 `ll-cli` 或 shell 调用。
6. 保持无障碍：已有 `Semantics`、Tooltip、焦点隔离和 48px 交互区不因视觉改造退化。

## 5. 非目标

1. 第一阶段不重构详情页信息架构。
2. 第一阶段不重做设置页、下载管理弹窗、环境管理弹窗的内部布局。
3. 不引入新功能、主题色选择器或动态壁纸式效果。
4. 不改变搜索、安装、更新、卸载、右键菜单、下载日志复制等业务契约。
5. 不为了视觉效果使用高成本全局毛玻璃。

## 6. 第一阶段范围

第一阶段覆盖：

- `AppShell`：主壳层外观、内容容器边界、普通窗口和最大化下的边距策略。
- `CustomTitleBar`：标题栏背景、搜索框默认底色、窗口按钮 hover。
- `Sidebar`：背景、选中态、hover、底部入口视觉统一。
- `SidebarInteractionSurface`：默认 hover / selected 色从旧灰底迁到新壳层令牌。
- `AppColorPalette` / `AppTheme` / `AppRadius`：浅色主题令牌调整，必要时增加语义化壳层色。
- `AppCard`：列表卡片轻边框、hover 边界和阴影节制。
- `ResponsiveAppGrid`：主列表页网格间距与底部 padding 的统一。
- 推荐、全部、排行、搜索、我的应用、更新页的顶层容器和列表区域。

## 7. 视觉规则

### 7.1 Shell 表面模型

Shell 采用三层：

1. Window root：主白色窗口体只负责基础背景，不在 Flutter 层裁剪四个窗口角，四角策略交给平台窗口管理器。
2. Shell chrome：标题栏和侧边栏所在的浅表面，接近白色，不使用明显灰块。
3. Content plane：右侧内容工作区，用极浅边框和较大圆角与 Shell chrome 区分。

浅色建议：

- `background`：保持白色或接近白色，作为窗口体。
- `surface`：白色，作为页面和卡片主表面。
- `surfaceContainerLow`：改为极浅中性色，只用于 hover / subtle fill，不作为大面积主背景。
- `cardBackground`：主列表卡片改为白色，边框负责层次。
- `borderSecondary`：使用比现有更浅的边框承接内容工作区和卡片边界。

深色主题第一阶段只做不破坏性跟随，避免浅色方案改动导致深色对比不足。深色保持现有层次为主，必要时同步轻微边框和 hover 规则。

### 7.2 标题栏

标题栏保持 57.6px 高度和现有窗口控制逻辑。视觉调整：

- 背景与窗口体一致或仅有极轻色差。
- 搜索框底色从较重灰改为极浅灰，focus 时回到白底 + 品牌色细边框。
- 窗口按钮 hover 使用极浅 hover fill；关闭按钮 hover 仍保留危险红，符合桌面预期。
- 不改变标题栏拖拽、双击最大化和候选浮层逻辑。

### 7.3 侧边栏

侧边栏保留当前宽度、折叠规则、静态菜单、动态菜单和底部入口。视觉调整：

- 默认背景与标题栏一致，避免像独立灰栏。
- 选中态改为 soft pill：浅主色底 + 主色图标文字 + 适度字重。
- 取消或弱化左侧蓝色竖条，避免激活态过重。
- hover 只用极浅填充，不能接近选中态强度。
- 底部三个入口与菜单项共用相同 hover / active 语言。

### 7.4 内容工作区

内容工作区是第一阶段最关键改动：

- 右侧内容容器从大面积灰底改成白色或接近白色的工作区。
- 用 1px 极浅边框和 12~16px 圆角表达边界。
- 普通窗口下保留轻边距，模拟 OpenCode 截图中的内嵌白色面板；最大化时边距可略收紧，但仍避免内容贴边。
- 底部不再露出明显灰条；滚动到底部时 footer 与工作区背景保持一致。
- `ClipRRect` 继续约束内容，避免轮播和列表越过圆角。

### 7.5 主列表卡片与网格

卡片继续走共享 `AppCard`，页面层只传 props，不让卡片订阅更多全局 Provider。

调整规则：

- 卡片背景为 `surface`。
- 默认态增加极浅边框，替代灰底分隔。
- hover 时边框略增强或加入很轻阴影，阴影透明度必须低，不能形成网页式浮卡。
- 圆角从 8px 可提升到 10~12px，但保持桌面工具感，不做过度圆润。
- 网格间距维持当前密度或略收敛，减少灰色沟槽感。
- 列表底部 padding 与分页 footer 统一，避免滚动到底出现单独底带。

### 7.6 主页面差异

- 推荐页：Banner 保持现有视觉能力，但外层边距和内容底色跟随新工作区；标题与卡片区减少灰底暴露。
- 全部应用页：分类筛选栏使用新浅表面，不使用重阴影；展开/折叠行为不变。
- 排行页：Tab 栏从硬分隔改为轻底或无底，保留胶囊选中态。
- 搜索页：`Scaffold` 背景跟随新内容工作区，结果头只做轻文字层级，不制造灰条。
- 我的应用页：头部 Tab、搜索框和列表卡片使用同一页面背景；搜索框填充从 `surfaceContainerLowest` 收敛到项目令牌。
- 更新页：更新列表卡片跟随 `AppCard` 语言，顶部区域只做轻面板，不扩展业务行为。

## 8. 代码边界

### 8.1 允许修改

- 主题令牌和主题映射。
- Shell、标题栏、侧边栏和侧边栏交互表面。
- 共享卡片和网格组件的视觉参数。
- 主列表页顶层容器、padding、背景和轻边框。
- 必要的 widget 测试或 golden 基线调整。
- 设计文档和项目规范中的视觉约定补充。

### 8.2 禁止修改

- `ll-cli` 调用链、安装/更新/取消/卸载流程。
- 应用详情接口、搜索接口、分页 Provider、缓存 key 语义。
- 路由结构和 KeepAlive 副作用暂停/恢复逻辑。
- 下载日志复制来源、安装队列任务身份和进程管理契约。
- 动态菜单接口或本地菜单规则。

## 9. 性能与无障碍

性能约束：

- 不使用全屏 `BackdropFilter`。
- 不在 `build` 中做图片解析、颜色采样或 IO。
- Shell 背景和边框使用普通 `Container` / `DecoratedBox`，避免复杂 painter。
- 列表继续使用 `CustomScrollView`、`SliverGrid`、`ListView.builder` 或 `ListView.separated`。
- hover 动画只改颜色、边框或很轻阴影，避免布局尺寸变化。

无障碍约束：

- 保留侧边栏 `Tooltip`、`Semantics(button/selected)`。
- 保留主列表区域 `Semantics(label: l10n.a11yAppListArea)`。
- 搜索框、标签模式、候选浮层键盘行为不变。
- 装饰性图标继续 `ExcludeSemantics`。
- 按钮和菜单交互区不因视觉缩小低于现有可点击尺寸。

## 12. 风险

1. Linux 透明窗口和 Flutter 绘制背景之间可能出现边缘黑底或锯齿，需要实际截图确认。
2. 最大化状态下如果仍保留外边距，可能看起来不像系统最大化窗口；需要在实现中按 `_isMaximized` 区分。
3. 全局调浅 `surfaceContainerLow` 会影响下载管理、环境管理等组件的灰底层级；第一阶段需要选择语义令牌时尽量避免破坏深层页面。
4. 卡片边框变浅后，低对比显示器上可能层级不足；hover 与默认边框要兼顾可见性。
5. 深色主题不是第一阶段主目标，但不能因浅色优化造成深色页面不可读。
